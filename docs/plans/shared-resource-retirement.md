## State and ownership contract

- Resource states are live, retirement requested/in progress, and completed. Keep `finished?` as the existing invalidated predicate so delivery and idle/drain loop checks keep their current meaning. Add a separate private completion predicate/helper for actual retirement. Use completion for ServerSession accept pruning, TLS drain selection, Accepted#wait_closed, and H2 Transport pruning. Delivery at connection.rb:393 continues to use invalidation. The numeric caps stay unchanged; a retiring server resource retains its max_connections slot until actual ownership ends. H2 connection_limit remains controlled by Async::Pool, whose retire deletes the pool slot before calling close; do not change that pool policy. Empty maps, raw closed state and an abort flag are insufficient completion evidence.
- One private cleanup task performs destructive retirement. Use `Async::Task.new(@lifetime, transient: true, finished: false)` for each session/resource cleanup owner. Pass the existing session/transport lifetime through a private resource anchor setter in accept, H1 replacement and H2 connect. Capture first abort error, set invalidation and assign the owner before calling run, without an intervening yield. Never directly cancel the cleanup task because Task#cancel clears transient. Do not add a hidden reactor, thread, global registry or public framework. Raw close is the first eager cleanup step and precedes listener/task joins and buffered/TLS cleanup. No required initiator work may follow launch because Cancel can arrive at launch.
- External abort callers join this cleanup task. Resource-owned initiators and live owned reentrants request retirement and return without waiting on that task. The cleanup task can then cancel and join the initiating task, including its final unwind, before disposal and publication. Do not define completion to exclude that initiator. Determine ownership before eager cleanup launch and preserve membership through task-tree reparenting. Do not broadly exempt unrelated external tasks.
- Owned roots include connection reader, registered writers, tracked setup/request/handler tasks, serve task, and explicit output task references. Capture roots and their non-transient descendants before cancellation can reparent them; do not absorb arbitrary application transient descendants that the existing lifecycle never cancels. Join the transient connection reader explicitly by identity. Ownership is sticky for the retirement: captured identities, live registry membership and descendants of owned ancestors remain owned even after writer-map removal or task reparenting. Re-scan live registered ownership until stable; prevent new writers from entering after invalidation, preserving nested writes already owned. Idle watcher and drain task are session/lifecycle coordinators, not automatically resource-owned members. Do not join a drain task that is waiting for the same retirement. Serve cancelling an idle watcher must not cancel the independent cleanup task.
- Mark root cancellation delivery before calling cancel. Cancel roots once and let the existing cascade handle ordinary descendants; do not independently send redundant descendant cancellations. Do not repeatedly cancel a task merely because its ensure remains live. Parent cancellation may still cascade repeated cancellation; held cleanup tests must tolerate it without pretending it completed. Join captured non-transient descendants explicitly because Task#wait can resolve before children finish. Require actual root Task#finished? after joining; it already ignores arbitrary transient children under the pinned task-tree contract.
- External waiter interruption cannot abandon the independent cleanup owner or publish completion early. Retain the waiter's first escaping interruption through the join and re-raise that same object after completed cleanup; competitors do not inherit another caller's interruption. Distinguish a joined task's stored failure from a new interruption of the joiner. Do not swallow fatal exceptions as ordinary task failures. This architecture prevents lifecycle/caller cancellation from interrupting raw-close disposal; it does not introduce descriptor retention or attempt to redesign native descriptors. If supported cancellation can still reach and strand raw close, stop and report before expansion.
- An external server close caller interrupted during nonzero graceful drain requests forced session retirement, joins actual cleanup, then re-raises its identical first exception. Later interruptions neither restart retirement nor abandon it. Normal uninterrupted close and any already-decided outcome remain unchanged. This is an explicit interruption-policy clarification; the base Affinity's separate closer does not establish the same policy for every waiter interruption.
- ServerSession must join shared resource retirement even when raw-close reenters serve cleanup or another abort is in progress. Use one deferred private session cleanup owner with the same transient lifetime anchor. A task owned by any session resource must not retain-and-continue on session cleanup or close waits: it requests retirement and returns, or remains plainly interruptible in the existing close wait, so cleanup can join it. The session cleanup task itself never waits on itself. Close coordinators are waiters, not work for that same cleanup owner to join. The lifetime guard is an external interruption-retaining joiner, not owned reentry; it must keep the hierarchy alive until session cleanup completes. Cleanup cancels the lifetime last, after publication, and never joins that guard. Do not publish session closed or clear admission/identity ownership early. Assign session cleanup before launch, and perform all peer raw closes and stop_accepting inside it, preserving all-peers invalidation before listener cleanup yields.
- Defer `finish_closed` publication until the final abort/cleanup join completes, including the close ensure path. Decide the outcome once and publish once: abort decides false, close_owned decides drained, and the first decided outcome wins. Ordinary close after resource-level invalidation retains today's true result once cleanup is joined; repeated/concurrent close shares the decided outcome. A drain's already-aborted and not-ready short-circuits must join resource retirement before preserving their true result. Changes to shared Affinity must preserve H2 Transport behavior and receive focused consumer evidence. Do not make an in-progress flag an early publication barrier.
- Startup, partial setup and ordinary graceful drain remain safe and preserve their current outcomes. New work must not acquire ownership after a published completion. Retain genuine cooperative/non-yielding limits in owning documentation.

Transient cleanup survives ordinary task cancellation, not reactor termination. It requires a non-transient external waiter or lifetime guard while cleanup is live. Completion-based resource retention lets close/abort find and join it. Do not promise completion after the application closes its reactor or ceases to keep it alive. H2 pool release/acquire/close can now join actual connection retirement; RPC deadlines do not bound that cooperative cleanup wait. Document this caller-visible latency limit without adding a timeout.

The implementer must spell out the final actors, ownership membership and join graph before product edits. Prefer a small private completion primitive/state within the owning lifecycle component. Do not add a public API/SPI or generalized framework. A material policy or surface change returns to the coordinator.
